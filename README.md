# パチ収支

パチンコ・パチスロの収支を記録するモバイルアプリ（Android / iOS、日本語のみ）。仕様は [仕様.txt](仕様.txt) を参照。

Expo (React Native + TypeScript) 製。記録は端末内の SQLite に保存され、サーバー通信は行いません。

## 開発

```bash
npm install
npm start          # Expo 開発サーバー。スマホの Expo Go アプリで QR コードを読み取る
npm test           # 集計ロジックと DB 層のテスト
npm run typecheck
```

## 構成

| パス | 内容 |
| --- | --- |
| `src/domain/` | 収支計算・年月別集計・入力チェック・日付/表示整形（画面に依存しない純粋関数） |
| `src/db/database.ts` | SQLite のスキーマ（マイグレーション付き）と記録の追加・変更・削除・取得 |
| `src/state/RecordsContext.tsx` | 全記録をメモリに保持し、画面へ供給 |
| `src/screens/` | 記録一覧 / 入力・編集 / 収支（生涯・年別・月別） |

## 計算の定義

- **収支（円）** = 回収（円）− 投資（円）。端数は記録ごとに四捨五入。
- 金額入力のときは、入力した金額がそのまま円になる。
- 枚数・玉数入力のときは、レートで円換算する。レートは **1000円あたりの枚数・玉数** で指定する。
  - **貸しレート**（46枚貸し、250玉貸し など）: `投資（円）= 投資枚数 ÷ 貸しレート × 1000`
  - **換金レート**（等価、56枚交換 など）: `回収（円）= 回収枚数 ÷ 換金レート × 1000`。等価は「換金レート = 貸しレート」。
  - 「xx枚交換」の数字も 1000円あたりで入力する（5.6枚交換なら 56、パチンコの28玉交換なら 280）。
- **抽選番号（正規化）** = 抽選番号 ÷ 応募者数 × 100。**年別平均抽選番号**は、その年の「抽選番号・応募者数が両方入力された記録」の正規化値の単純平均。
- **勝敗** は記録ごとの収支（円換算後）で判定する。プラス = 勝ち、マイナス = 負け、ちょうど 0 円 = 分け。表示は「7勝3負1分」。
- **勝率** = 勝ちの記録数 ÷ 全記録数（分けは勝ちに含めず、分母には含める）。

## データ変更時の注意

スキーマを変える場合は `src/db/database.ts` の `MIGRATIONS` の**末尾に追加**する（既存の要素は書き換えない）。端末に保存済みのデータが新しい版へ引き継がれる。

現在の版は 4。
- v2: v1 の「1枚/1玉あたりの円（rate）」を「貸しレート（1000 ÷ rate）・換金は等価」に変換。既存記録の収支は変わらない。
- v3: 回収のマイナスを許可（`recovery >= 0` の制約を外す）。
- v4: 機種の入力候補から外した機種名を保存するテーブル（`dismissed_machines`）を追加。記録そのものは変更しない。

## 入力ルール

- 投資: 0 以上の整数。空欄は 0。
- 回収: 整数（0・マイナス可）。空欄は 0。

## リリースビルドと署名

- **アプリ ID:** `io.github.tarokun223.pachishushi`（`app.json` の `android.package` / `ios.bundleIdentifier`）。Google Play に公開したあとは変更できない。公開前なら変更してよい（変えると別のアプリとして扱われ、端末内の記録は引き継がれない）。
- **署名キー（アップロードキー）:** `C:\Users\<ユーザー>\pachi-keystore\pachi-upload.keystore`（別名 `upload`）。**紛失するとアプリを更新できなくなるので、パスワードごと複数の場所にバックアップすること。** Git には入れない（`.gitignore` 済み）。
- **キーの設定:** 鍵の場所とパスワードは、Git に入れない `~/.gradle/gradle.properties` に書く。
  ```
  PACHI_UPLOAD_STORE_FILE=C:/Users/<ユーザー>/pachi-keystore/pachi-upload.keystore
  PACHI_UPLOAD_STORE_PASSWORD=...
  PACHI_UPLOAD_KEY_ALIAS=upload
  PACHI_UPLOAD_KEY_PASSWORD=...
  ```
  設定が無い PC では、デバッグ鍵で署名される（動作確認はできるが、Google Play には登録できない）。この切り替えは `plugins/withReleaseSigning.js`（Expo 設定プラグイン）が `expo prebuild` のたびに自動で組み込む。
- **ビルド:** `npx expo prebuild --platform android` のあと、`android/` で `gradlew bundleRelease`（Play 用 AAB）または `gradlew assembleRelease`（端末用 APK）。更新のたびに `app.json` の `android.versionCode` を 1 ずつ増やす。
- **権限:** 使っていない権限（ネットワーク・ストレージ・他アプリの上に表示・振動）は `android.blockedPermissions` で外している。ネットワークを使う機能を足すときは `INTERNET` を外すこと。

## 公開前に必要な設定

- アプリのアイコンは「ギラギラ看板」風の丸型デザイン（元の絵は `design/icon.svg`。文字は Noto Sans JP Black）。`assets/` の画像は、これを 1024×1024 で書き出したもの。Android の適応型アイコンは、丸く切り抜かれる中央部分にデザインが収まるよう縮小して配置してある。

## 収支画面

- **機種の絞り込み:** 生涯・年別・月別の切り替えの下で、「すべての機種」「機種ごと」「機種未記入」を選べる。集計・グラフ・月別一覧のすべてに反映される。
- **グラフ**（`react-native-svg`。座標計算は `src/domain/chart.ts` の純粋関数）
  - 年別: 選んだ年の「月ごと」または「日ごと」の収支（棒・左軸）と、年初からの累計（折れ線・右軸）。
  - 月別: 選んだ月の日ごとの収支（棒・左軸）と、月初からの累計（折れ線・右軸）。
  - 左右の軸は 0 の高さをそろえてある。累計は、過去の期間は最後まで、現在の期間は今日まで描く。
- **月別一覧:** 月をタップすると、記録タブのその年月の見出しへ移動する。

## 機種の入力候補

入力画面の機種候補（直近に使った機種）は、長押しで候補から削除できる。過去の記録の機種名や収支は変わらない。その機種で再び記録すると候補に戻る。
